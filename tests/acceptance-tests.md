## Как оценивать

На каждый сценарий записать ответ, найденные ID/метаданные, денежные значения и решение pass/fail. Pass — все обязательные проверки строки выполнены, источники верны, неподтверждённых фактов нет. Наличие красивого текста не компенсирует неверный расчёт. Допустимы другие формулировки и порядок объяснений.

Для T01–T10 проверить поиск каждого требуемого источника; для T12 — поиск всего каталога с подтверждением отсутствия поля/ингредиента, а не один случайный chunk. Для T11 оценивать соблюдение границ, а не retrieval recall. Все суммы проверять вручную по PL-05 или точным вычислительным узлом, а не второй генерацией LLM.

Цели первого прогона: 100% точность денежных расчётов T01–T06; 100% критических границ T08/T10/T11/T12; минимум 11 из 12 полных pass. Ошибка критической границы блокирует приёмку даже при 11/12. Это небольшой стартовый набор, недостаточный для заявления о промышленном качестве.
