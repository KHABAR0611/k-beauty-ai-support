# Публикация и порядок сопровождения

Публичный репозиторий: [KHABAR0611/k-beauty-ai-support](https://github.com/KHABAR0611/k-beauty-ai-support). Основная ветка main; первый commit содержит только актуальную поставку, без прежней .git и личных материалов. Origin настроен на `https://github.com/KHABAR0611/k-beauty-ai-support.git`. Первый push commit `47c625636e523f0b922cb5ba910249aeb861269a` выполнен и проверен. История до чистого root commit в публичный Git не импортируется.

Клонирование и обычная синхронизация:

```text
git clone https://github.com/KHABAR0611/k-beauty-ai-support.git
cd k-beauty-ai-support
git remote -v
git push origin main
git rev-parse HEAD
git ls-remote --heads origin main
```

Авторизация GitHub CLI хранится в системном credential store; рабочий checkout использует repo-local credential helper. На другой машине выполните безопасный вход через `gh auth login` и настройте credential helper либо SSH. Не добавляйте токен в URL или .env.example. Не применяйте force push. При ошибке авторизации или конфликте веток остановите публикацию и сообщите причину.

После каждого завершённого и успешно протестированного инженерного блока создавайте commit с ясным сообщением, выполняйте обычный push в origin/main и проверяйте совпадение удалённого и локального SHA. Сообщайте commit hash и ссылку на GitHub. Правило закреплено в корневом `AGENTS.md`.

Дальнейшие изменения ведутся только здесь. Предыдущий локальный репозиторий остаётся архивом, без параллельных активных ветвей и обратной синхронизации. Личные заметки ведутся вне публичного checkout; learning/ также исключён из Git и Docker context как защитная мера. Публичные инженерные ADR остаются в docs/.
