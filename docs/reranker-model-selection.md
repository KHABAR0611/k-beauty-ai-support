# Выбор cross-encoder

Решение для CPU-конфигурации с 8 ГБ RAM: `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`, официальный FP32 ONNX, revision `1427fd652930e4ba29e8149678df786c240d8825`. Выбор основан на языке, лицензии, размере и возможности использовать установленный runtime. Качество на текущем корпусе проверяется отдельно; число загрузок модели не является критерием выбора.

Пара query/document до 512 токенов | ONNX FP32 470 883 696 байт, примерно 118M параметров | Наименьший из трёх FP32 weight footprint; реальные CPU latency/RAM приведены в результатах Блока 4 | Apache-2.0; официальный ONNX и tokenizer; без remote Python, Transformers и PyTorch |

GPU-инференс не выполнялся ни для одного кандидата. Доступная GTX 660M не подтверждена как совместимый ускоритель выбранного стека; CUDA-зависимости не установлены. Поэтому численные GPU latency отсутствуют. У невыбранных моделей также нет выдуманных CPU-бенчмарков или утверждения об их сравнительном качестве на K-Beauty.

MiniLM использует 12 слоёв, hidden size 384 и один классификационный logit. На каждой паре запускается совместное внимание query/document; это не cosine между embeddings. Сортировка по raw logit убывает, Identity соответствует конфигурации checkpoint. Значение не интерпретируется как вероятность или уверенность ответа.

Выбран стандартный FP32 export, а не файл с AVX2 в имени: CPU i5-3470S старый, пригодность целевой квантованной оптимизации не подтверждена. ONNX Runtime тот же, что для BGE-M3; новые тяжёлые зависимости не добавлены. Два CPU-потока, batch=1, отключён CPU memory arena; модели работают последовательно в одном процессе. Полные измерения памяти должны учитывать обе модели, библиотеки, activations и paging.

Контрольные суммы всех пяти файлов и размер закреплены в `src/kbeauty_support/retrieval/reranker.lock.json`. Загрузчик получает файлы только по immutable revision, проверяет размер/SHA-256 и не исполняет код репозитория модели. Проверка повторяется при создании adapter. Текст документа, числа, SKU и контекст исключений передаются полностью; пары длиннее 512 токенов вызывают явный fallback, а не скрытое усечение.

Primary pool=10, final_k=5, prefetch=20 зафиксированы до inference вместе с независимыми десятью запросами в коммите `a82a9ee`. Pool=5/15 — диагностика на исходных 13 запросах. Holdout запускается только на primary pool=10 и не используется для выбора модели или настройки. Модель, threshold и boosts по результатам holdout не меняются.
